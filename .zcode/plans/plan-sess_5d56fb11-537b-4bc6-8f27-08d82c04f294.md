# Server backups + quick node relocation (chain auto-heal)

## Контекст (из исследования кодовой базы)

Identity ноды (Host + NodeInfo + transit-ключи + standalone inbounds) уже хранится атомарно/зашифрованно в `store.json`. Relocation технически = обновить `Addr` в 3 местах + re-apply, переиспользуя persisted transit-ключи. Но есть **блокирующий баг**: `ResolveNodes` (`store.go:436-449`) копирует только `Port, TransitPrivKey, TransitShortID, TransitUUID, Inbounds` — дропает `Role, ExitTargets, TransitAWG*, ExitAWG*, ExitAWGLinks`. Из-за этого AWG-цепи ломаются не только при relocate, но и при любом re-apply после рестарта процесса (ключи регенерируются → линки рвутся). Чиню первым.

## Этап 1 — Fix `ResolveNodes` (базовый баг, блокер для всего)

**`internal/chain/store.go:436-449`** — расширить struct literal копированием ВСЕХ persisted-полей ChainNode:
`Role, ExitTargets, TransitAWGServerPriv/Pub, TransitAWGClientPriv/Pub, TransitAWGAddress, TransitAWGClientPort, ExitAWGServerPriv/Pub, ExitAWGListenPort, ExitAWGLinks`.

**Тесты** (`store_test.go`): `TestResolveNodes_PreservesAllTransitFields` — seed chain node со всеми полями заполненными → `ResolveNodes` → assert каждое поле сохранено (включая AWG/exit/role). `TestResolveNodes_ReapplyKeepsAWGKeys` — двойной `ResolveNodes` не теряет AWG-ключи. Этот фикс сам по себе закрывает латентный re-apply баг для AWG-цепей (отдельная ценность).

## Этап 2 — Backups (экспорт панели + пер-нода)

### 2A. Backend store helpers (`store.go`)
- `(s *Store) ExportNode(id string) (*NodeBackup, error)` — собирает `NodeBackup{Host, NodeInfo, ChainMemberships []ChainMembership}` где `ChainMembership` = срез ChainNode для этого ID + имя цепи (чтобы restore знал в какие цепи узел входит). ErrHostNotFound если ID нет.
- `(s *Store) ImportNode(b *NodeBackup, force bool) error` — восстанавливает Host + NodeInfo; для chain-memberships обновляет существующие ChainNode по ID (или добавляет если force и цепь есть). Dedup по ID: существующий ID с другим Addr → skip без force, overwrite с force.
- `(s *Store) ExportStore() ([]byte, error)` — весь `storeFile` как JSON (для полного бэкапа панели).
- `(s *Store) ImportStore(data []byte, force bool) error` — заменяет всё (force) или no-op если store не пустой без force.

### 2B. HTTP handlers (`internal/web/backups.go` — новый файл)
По образцу `handleExportKeys`/`handleImportKeys` (`settings.go:385/398`):
- `GET /ui/backup/store` → `Content-Disposition: attachment; filename="angry-box-store-<ts>.json"` → `ExportStore()`.
- `GET /ui/backup/nodes/{id}` → `attachment; filename="angry-box-node-<id>.json"` → `ExportNode(id)`.
- `POST /ui/backup/import` → принимает `store_json` или `node_json` + `force` → `ImportStore`/`ImportNode`. Рендерит alert-success/error.

Регистрация в `server.go` Register (под `s.auth`).

### 2C. UI (`web/templates/settings.templ` + `nodes.templ`)
- Settings: секция "Backups" — кнопки "Export panel" (`href=/ui/backup/store download`) + "Import" (toggle form → `/ui/backup/import`).
- Nodes: на строке ноды — кнопка "Export" (`href=/ui/backup/nodes/{id} download`, ghost btn-xs, рядом с Apply).
- i18n: ключи "Backups", "Export panel", "Import backup", "Export node", "Node imported", "Store imported", "Invalid backup JSON" (en+ru, parity).

### 2D. CLI (`cmd/angry-box/main.go`)
- `angry-box backup store -o <file>` — пишет `ExportStore()` в файл (или stdout).
- `angry-box backup node <id> -o <file>` — `ExportNode(id)`.
- `angry-box restore <file> [--force]` — авто-detect (store vs node по JSON-полям) → `ImportStore`/`ImportNode`.

## Этап 3 — Node relocation (UI кнопка + CLI, auto-heal зависимых)

### 3A. Backend relocate logic (`internal/chain/relocate.go` — новый файл)
`func RelocateNode(ctx, store, applier, nodeID, newAddr, newUser, newKeyPath string) (*RelocateReport, error)`:

1. Валидация: `GetHost(nodeID)` → ErrHostNotFound. `newAddr` parse.
2. Сохранить oldAddr для лога/audit.
3. Обновить Addr (и опц. User/KeyPath) в 3 местах:
   - `Host` (`SaveHost`)
   - `NodeInfo.Host` (`SaveNodeInfo`)
   - `ChainNode.Addr` для каждой цепи содержащей nodeID (`SaveChain`) — snapshot-консистентность.
4. Сборка списка affected chains = `GetChainsForNode(nodeID)`.
5. Для каждой affected цепи: `ResolveNodes` (теперь корректно после Этап 1) → `ApplyChain`. ApplyChain redeployит: сам N (на новый VPS, переиспользуя transit-ключи), N-1 (его outbound embeds `extractHost(N.Addr)` = новый IP), и balancer'ы на N если N exit (`awg-exit-nX` endpoint embeds N.Addr, `awg_deploy.go:179`).
6. `RelocateReport{NodeID, OldAddr, NewAddr, Chains []{Name, Success, Error}}`.
7. Audit log entry ("node relocated X→Y, chains redeployed").

Параллельность: redeploy цепей последовательно (цепи могут sharing узлы — serialized через existing `withHostLock`).

### 3B. HTTP handler (`internal/web/nodes.go`)
`POST /ui/nodes/{id}/relocate` — модалка: `new_addr` (required) + опц. `new_user`, `new_ssh_key_id`. Вызывает `RelocateNode`. Рендерит `ApplyResult`-style сводку (success/error per chain). Под `s.auth` + CSRF (existing middleware).

### 3C. UI (`web/templates/nodes.templ`)
На строке ноды — кнопка "Relocate" (ghost btn-xs, рядом с Apply/Export) → открывает modal в `#modal-container` (DaisyUI pattern, как existing capture/inbounds modals) с формой: new addr input + опц. user/key dropdown + `hx-post=/ui/nodes/{id}/relocate` + `hx-target=#modal-container`. i18n ключи: "Relocate node", "New address", "Relocate to new VPS", "Node relocated", "Relocate failed" (en+ru).

### 3D. CLI (`cmd/angry-box/main.go`)
`angry-box relocate <node-id> --addr <new-ip:port> [--user <user>] [--key <key-id>]` → `RelocateNode` → печатает report (per-chain success/error). Добавить в top-level switch + usage.

## Что НЕ в скоупе (явно)
- Авто-detect заблокированной ноды (health-check → auto-relocate) — отдельная фича, требует monitoring; сейчас оператор решает что заблокировано.
- Backup на удалённое хранилище (S3/SSH) — сейчас download/upload через UI/CLI, оператор хранит файл сам.
- Relocate с заменой transit-ключей (rotation) — сейчас deliberately переиспользуем persisted ключи (чтобы other nodes/clients не перенастраивать). Rotation — отдельный follow-up.
