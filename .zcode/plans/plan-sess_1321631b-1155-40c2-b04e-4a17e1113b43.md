# P1a — Стейт-машина здоровья ноды (только liveness, алерт + аудит)

**Скоуп:** Заменить бинарный `NodeMetrics.Online bool` на настоящую стейт-машину (`healthy → suspect → down → unreachable` + оператор-маркированный `blocked`), считаемую из существующего цикла метрик с **гистерезисом** (один дропнутый SSH-пакет не должен дёргать ноду). Показывать состояние везде, где сейчас фейковый «green = online» (точка статуса в spider, бейдж дашборда, ячейка статуса в таблице нод) + писать событие аудита на каждый **переход** (не на каждый тик). Без новой инфры, без авто-релокейта, без sentinel-проба — всё это явно отложено.

**Решения (подтверждены вами):**
- **Источник обнаружения = только стейт-машина liveness** (сигналы SSH+systemd, которые уже собираются через `GetStatus`). «Заблокирован DPI» — это **оператор-маркированное** состояние (кнопка в UI), НЕ авто-обнаруживается — оркестратор SSH'ит из свободного региона и физически не видит DPI-блок. Sentinel-проб (точка наблюдения из цензурированного региона) — чистое будущее расширение за плаггабельным интерфейсом `Probe`; разделение `classifyProbe`/`NextState` делает эту точку расширения чистой.
- **Авто-действие = только алерт + аудит.** Без авто-отключения инбаундов, без авто-релокейта. Оператор видит состояние + кнопку «Mark blocked / Clear block» и решает сам (кнопка Relocate уже умеет делать сам переезд).

## A. Модель данных (`internal/domain/model/panel.go`)

**`NodeMetrics` (panel.go:202-215)** — аддитивные `omitempty` поля (без миграции; стор загружает неизвестный JSON толерантно):
- `State string` — одна из констант `NodeState*`
- `StateReason string` — «ssh dial: timeout», «sing-box inactive», «operator marked», ""
- `StateChangedAt time.Time` — когда вошли в текущее состояние
- `ConsecutiveFails int`, `ConsecutiveOKs int` — счётчики гистерезиса
- `Online bool` ОСТАЁТСЯ (обратная совместимость, в цикле выводится из State)

**Новые строковые константы** (зеркалит `Source*` в panel.go:185 + строки `Status` юзера в panel.go:91 — конвенция проекта = строковые константы, без enum-типа):
```
NodeStateHealthy / NodeStateSuspect / NodeStateDown / NodeStateUnreachable / NodeStateBlocked / NodeStateUnknown
```

**Конфиг гистерезиса:**
```go
type HysteresisConfig struct {
    DownThreshold    int `json:"down_threshold,omitempty"`    // подряд фейлов → down/unreachable (по умолч. 3)
    RecoverThreshold int `json:"recover_threshold,omitempty"` // подряд ок → healthy (по умолч. 2)
}
var DefaultHysteresis = HysteresisConfig{DownThreshold: 3, RecoverThreshold: 2}
```
**Зачем гистерезис:** один тик 15 мин, попавший на транзитный SSH-таймаут, НЕ должен флипать ноду в «down» — это спамит аудит + дёргает бейдж. 3 фейла подряд (~45 мин) до down; 2 ока подряд до восстановления. В этом слайсе хардкод; P1a+ подключит `PanelSettings.Hysteresis`.

## B. Стейт-машина — `internal/chain/nodehealth.go` (НОВЫЙ, чистый, unit-тестируемый)

Зеркалит паттерн `User.ComputeStatus()` (P0b). Две функции:

- `NextState(m *model.NodeMetrics, probe ProbeOutcome, cfg model.HysteresisConfig) (changed bool)` — мутирует `m` in place. `blocked` **липкий**: пробы его не сбрасывают (восстановительные пробы не авто-разблокируют; только хендлер оператора очищает).
- `SetNodeState(m, state, reason)` — для пути оператор-блокировки + тестов.

**`ProbeOutcome{SSHOK bool, Running bool, Reason string}`** — сырой результат одного тика.

Таблица переходов (задокументирована в док-комменте функции):

| текущее | проба | fails | oks | следующее |
|---|---|---|---|---|
| healthy | ok | 0 | — | healthy |
| healthy | fail (SSH) | 1-2 | — | suspect |
| healthy | fail (SSH) | ≥3 | — | unreachable |
| healthy | fail (systemd) | ≥3 | — | down |
| suspect | ok | reset | 1 | suspect (надо 2) |
| suspect | ok | reset | ≥2 | healthy |
| suspect | fail (SSH) | ≥3 | — | unreachable |
| suspect | fail (systemd) | ≥3 | — | down |
| down/unreachable | ok | reset | ≥2 | healthy |
| down/unreachable | fail | ++ | — | остаётся (счётчик с крышкой) |
| blocked | * | — | — | blocked (липкий) |
| unknown | ok | 0 | ≥1 | healthy |
| unknown | fail | ≥3 | — | unreachable/down |

## C. Интеграция в цикл метрик (`internal/web/server.go:126-150`)

Переписать `collectAllMetrics` — классифицировать каждую пробу + вызывать `NextState` + писать событие аудита **только на переходе**:

```go
for _, h := range hosts {
    status, err := b.GetStatus(ctx, *h)
    probe := classifyProbe(err, status)         // SSHOK/Running/Reason
    m := st.GetMetrics(h.ID)                     // durable (store.go:698)
    if m == nil { m = &model.NodeMetrics{HostID: h.ID, State: model.NodeStateUnknown} }
    m.LastChecked = time.Now(); m.LatencyMs = latency
    // ... заполнить Version/OS/Installed из status при err==nil
    oldState := m.State
    chain.NextState(m, probe, model.DefaultHysteresis)
    m.Online = m.State == model.NodeStateHealthy  // back-compat bool
    st.SaveMetrics(m)
    if m.State != oldState && oldState != "" {
        chain.WriteAudit(st, "health", "node", h.ID,
            chain.AuditPayload{"from": oldState, "to": m.State, "reason": m.StateReason}, "system")
    }
}
```

`classifyProbe(err, status)`: `err!=nil` → `{SSHOK:false, Reason:"ssh dial: "+shortErr(err)}` (первая строка, ~80 симв); `err==nil && !status.Running` → `{SSHOK:true, Running:false, Reason:"sing-box inactive"}`; иначе `{SSHOK:true, Running:true}`. **GetStatus/бэкенд не трогаем** (без разрастания скоупа) — ошибку классифицирует вызывающий.

**Дисциплина локов:** `GetMetrics`/`SaveMetrics` каждый берёт свой лок; read-modify-write разрыв безопасен, потому что `collectAllMetrics` — единственный writer-горутин метрик (server.go:101-113). Хендлер оператора block/unblock — второй writer, но идёт через тот же `SaveMetrics` (per-call лок); потерянный апдейт просто реклассифицируется следующим тиком. Документировано комментом.

Зеркалит паттерн `handleTrustHostKey` (dashboard.go:42):

## I. Риски (помечены)

1. **«Blocked» НЕ авто-обнаруживается** — по дизайну. UI обязан говорить «Mark as blocked» (действие оператора), не «Detected blocked». Честный скоуп; sentinel-проб это P1a+ за интерфейсом `Probe` (будущий `SentinelProbe` вернёт более богатый `ProbeOutcome{Blocked bool}` — `classifyProbe` точка подмены).
2. **Гистерезис хардкод** в этом слайсе. Норм — 3 фейла на 15-мин интервале = 45 мин до флага. P1a+ подключит `PanelSettings.Hysteresis`.
3. **Два writer'а** (collectAllMetrics + хендлер оператора) оба идут через per-call лок `SaveMetrics`; потерянный апдейт реклассифицируется следующим тиком. Приемлемо для 15-мин цикла; задокументировано. (Если ревьюер захочет хард-безопасность — добавить `UpdateMetrics(hostID, func(*NodeMetrics))` locked-хелпер; отложить, если не помечено.)
4. **Спам аудита** — только переходы + гистерезис глушит; флапающая нода всё равно пишет 2 события на флап, но RecoverThreshold=2 ограничивает. Приемлемо; помечено.
5. **Обратная совместимость** — старые `NodeMetrics{Online:true, State:""}` рендерятся как `healthy` через вывод. Без миграции.
6. **Смена сигнатуры `spiderNodes`** — добавление `metricsByHost` трогает все call-сайты. Мелочь.
