# P1b/P2a follow-up — три мелочи (один заход)

Три точечные правки, закрывающие дыры из §18/§19. Каждая независимо компилируется и тестируется. Никакого e2e/VPS — чистый код + unit-тесты.

**Решение (подтверждено):** retention = `ls + rm` на offsite-таргете (реальная серверная ротация).

## Fix 1 — Свежий AWG /24 при клоне (`internal/chain/clone.go` + `cryptogen.go`)

**Проблема:** `cloneInbounds` (clone.go:213) копирует `AWGServerAddress` как есть — клон в той же цепочке конфликтует subnet с source (оба `10.8.0.1/24`).

**Решение:** заменить «копировать» на «выделить свободный /24». Существующего хелпера нет (разведка подтвердила) — пишу `allocateAWGServerSubnet(taken []string) string` в `cryptogen.go`:

```go
// allocateAWGServerSubnet picks the first free 10.8.X.0/24 (X = 1..250) not in
// `taken` (a list of existing AWGServerAddress CIDRs across the store), and
// returns "10.8.X.1/24" (server addr = .1 of the /24). 10.8.0.0/24 is reserved
// as the legacy chain-entry default, so allocation starts at 10.8.1.0/24.
// Returns the legacy default "10.8.0.1/24" if all are taken (extremely unlikely;
// flagged as a known collision — operator can edit the inbound).
func allocateAWGServerSubnet(taken []string) string
```

Поток в clone.go:
- `CloneNode` собирает `takenSubnets` из store: `store.ListNodeInfos()` → для каждого `info.Inbounds` где `Protocol=="awg"` + `AWGServerAddress != ""` → добавить. Плюс source-нода (хотя она уже в ListNodeInfos). Передаёт в `cloneInbounds(src, takenSubnets)`.
- `cloneInbounds` для AWG-инбаунда: вместо `AWGServerAddress: ib.AWGServerAddress` → `AWGServerAddress: allocateAWGServerSubnet(taken)` (и добавить выделенный в `taken`, чтобы два AWG-инбаунда в одном клоне не получили один /24). Для не-AWG инбаундов `AWGServerAddress` не важен — оставляем пустым (как было).
- Только AWG-инбаунды получают subnet (`ib.Protocol == "awg"`); остальные игнорируем.

**Тесты** (`clone_test.go` дополнить / новые):
- `TestAllocateAWGServerSubnet_Free` — taken=[] → `10.8.1.1/24`; taken=[`10.8.1.1/24`] → `10.8.2.1/24`.
- `TestAllocateAWGServerSubnet_SkipLegacy` — никогда не возвращает `10.8.0.0/24`.
- `TestCloneNode_AWGSubnetFresh` — source с AWG inbound `10.8.0.1/24`, клон получает `10.8.1.1/24` (distinct), source untouched. Посев через NodeInfo с awg-инбаундом.

## Fix 2 — Offsite retention/rotation (`backup_offsite.go` + `model` + `backups.go` + `settings.templ`)

**Проблема:** `PushOffsiteBackup` (backup_offsite.go:79) пишет в фиксированный `cfg.RemotePath` — перезапись, нет истории.

**Решение:** timestamp-имя + `ls`/`rm` ротация, оставляя `cfg.Retention` (default 5) блобов.

### A. Модель (`model.OffsiteBackupConfig`, panel.go:162) — добавить:
```go
Retention int `json:"retention,omitempty"` // 0 = default 5; blobs kept on the offsite target
ScryptN   int `json:"scrypt_n,omitempty"`   // 0 = default 2^16 (Fix 3)
```

### B. Ядро (`backup_offsite.go`):
- `cfg.RemotePath` теперь — это **директория** на offsite-таргете (напр. `/home/backup/angry-box`). Блоб пишется в `<RemotePath>/angry-box-<ts>.abbkp` (ts = `time.Now().UTC().Format("20060102-150405")`, переиспользую из backups.go).
- После `UploadText`: если `Retention > 0` (default 5, считаем `<=0` → 5):
  - `ls -1 <RemotePath>/angry-box-*.abbkp` через `client.Run` → парсим имена → сортируем (имя содержит ts, лексикографическая сортировка = хронологическая, т.к. формат `20060102-150405`).
  - Если количество > Retention — `rm <RemotePath>/<старые N-Retention имён>` (по одному `rm` или батчем `rm a b c`).
  - Ошибки `ls`/`rm` — best-effort: лог + non-fatal (блоб уже на месте; ротация — nice-to-have, не блокер). Возвращаем nil (push успешен).
- `cfg.RemotePath` semantic shift: было «путь к файлу», стало «директория». Документирую в struct-комменте + UI placeholder. Существующие настройки: operator, настроивший `/home/bk/ab.abbkp`, получит блобы в `/home/bk/ab.abbkp/angry-box-<ts>.abbkp` (путь-как-директория) — back-compat: работает, просто структура меняется. Флаг в migration-ноте в §19-update.

### C. Handler (`backups.go` `handleSaveOffsite`): читать `offsite_retention` + `offsite_scrypt_n` из формы → `cfg.Retention`/`cfg.ScryptN`. (ScryptN — Fix 3, но форма одна.)

### D. UI (`settings.templ`): добавить поля "Retention (keep N blobs)" + "scrypt N (memory/paranoia)" в offsite-карточку. 2 новых i18n-ключа.

### E. Тесты (`backup_crypto_test.go`/новый `backup_offsite_test.go`):
- `TestPushOffsiteBackup_Rotation` — fake-SSH: правило `ls ` → out со списком из 7 старых имён + новый запишется → после push должны остаться 5 (2 `rm` вызваны). Проверить через `client.Commands()` что `rm` вызывался для 2 старых.
- `TestPushOffsiteBackup_RotationDisabled` — `Retention=0` → default 5 всё равно ротирует (т.к. `<=0 → 5`). Или сделать `Retention=-1` = off? Проще: `<=0 → default 5` всегда ротирует; `Retention` field >0 всегда. Без "выключить ротацию" — она всегда on (default 5). Флаг: если operator хочет без ротации — ставит большое число.
- `TestPushOffsiteBackup_TimestampPath` — upload path содержит `angry-box-` + ts-паттерн (regex).

**Fake-SSH нюанс:** `fakeSSHClient.Run(cmd)` матчаит по substring (fakessh_test.go:92). Скриптую правило `{substring:"ls ", out:"angry-box-20260709-000000.abbkp\nangry-box-20260709-010000.abbkp\n..."}` + `rm` правило `{substring:"rm ", out:""}`. Проверяю `client.Commands()` содержит 2 `rm`.

## Fix 3 — Тюнимый scrypt N (`backup_crypto.go` + `backup_offsite.go` + модель из Fix 2)

**Проблема:** `EncryptBackup` (backup_crypto.go:60) хардкод `backupScryptN=1<<16`. ~64MB на backup. На слабом оркестраторе тяжело.

**Решение:** `EncryptBackup` принимает опциональные N/r/p. Чтобы не ломать 11 существующих тестов (все зовут `EncryptBackup(plain, pass)`) — добавлю `EncryptBackupWithParams(plaintext, passphrase, N, r, p)` + оставлю `EncryptBackup(plaintext, passphrase)` как тонкую обёртку с дефолтами:

```go
func EncryptBackup(plaintext []byte, passphrase string) ([]byte, error) {
    return EncryptBackupWithParams(plaintext, passphrase, backupScryptN, backupScryptR, backupScryptP)
}
func EncryptBackupWithParams(plaintext []byte, passphrase string, N, r, p int) ([]byte, error) { ... }
```

`DecryptBackup` уже читает N/r/p из блоба — БЕЗ изменений (старые/новые блобы с разными N расшифровываются). `deriveBackupKey` уже принимает N/r/p.

`PushOffsiteBackup` (backup_offsite.go:63): `EncryptBackup(plain, cfg.Passphrase)` → `EncryptBackupWithParams(plain, cfg.Passphrase, scryptN, backupScryptR, backupScryptP)`, где `scryptN := cfg.ScryptN; if scryptN <= 0 { scryptN = backupScryptN }`.

**Тесты:**
- `TestEncryptBackupWithParams_LowN` — N=2^12 (быстрее) → roundtrip работает + блоб декодируется с тем же passphrase.
- `TestDecryptBackup_ReadsParamsFromBlob` — encrypt с N=2^14, decrypt без указания N (читает из заголовка) → OK. (Уже неявно покрыто существующими тестами с дефолт-N, но добавлю явный low-N кейс.)

## Риски (помечены)

1. **`cfg.RemotePath` semantic shift** (Fix 2) — было «файл», стало «директория». Существующие настройки работают (блоб пишется в `<путь>/angry-box-<ts>.abbkp`), но структура меняется. Документирую в §19-update + UI placeholder показывает «директория».
2. **`ls`/`rm` best-effort** (Fix 2) — ошибки ротации не фейлят push (блоб уже на месте). Логируется. Если offside-таргет не поддерживает `ls -1`/`rm` (редкость) — блобы копятся, но backup работает.
3. **`ls` parsing** (Fix 2) — `ls -1` даёт по имени на строку; парсю по `\n`, фильтрую `angry-box-*.abbkp`. `ls` может вернуть с путями или без — использую `ls -1 <dir>` (без путей) и собираю полный путь для `rm`.
4. **AWG subnet allocation** (Fix 1) — `10.8.X.0/24` для X=1..250; 250 подсетей. Если все заняты (250 нод с AWG) — fallback на legacy default + флаг. Нереалистично.
5. **scrypt N too low** (Fix 3) — operator может поставить N=2^10 (быстро, слабая защита). Документирую: «N=2^16 default — ~64MB/~100ms; ниже = слабее к brute-force». Не валидирую минимум (operator's choice; P2a+ — min floor).

## Явные не-цели

Без e2e SSH-ротации (мок-fake). Без retention-счётчика в сторе (серверная ротация через ls/rm, состояние только на offside-таргете). Без UI-валидации scrypt N (operator's choice). Без миграции RemotePath (semantic shift задокументирован, оператор правит путь при желании).
